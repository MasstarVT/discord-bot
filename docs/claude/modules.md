# Feature module reference

Read the one section you need. One subsection per module, then core commands. Hooks are written `event:hookId`.

Setup pickers that a feature writes to or hands out (destinations, reward and panel roles, categories) have a `new_<picker>` companion that creates the role or channel instead (`src/utils/newTargets.js`, see architecture.md › Safe utilities). Filters (exempt/ignore/allowed/denied/required/bonus), ping roles, lookups, one-off send channels and remove subcommands deliberately have none. A new setup picker should get one.

### 🔨 Moderation — `moderation`
- **Commands:** `/ban /kick /softban /timeout /unmute /unban /warn /case /purge /slowmode` MODERATOR (`/case history` lists a member's cases); `/case clear-history` ADMIN; `/modconfig` ADMIN.
- **Code:** `src/plugins/moderation.js`, `src/services/moderationService.js`. `executeModAction` is the only punishment path (`source` in `MOD_SOURCES`): never throws, Discord action first, a failure records nothing. `createInfraction` only records (still DMs, logs, escalates WARN). `isImmune`; `sendModLog` ignores `loggingEnabled`.
- **Rules:** `/timeout` max 28 d (longer = mute role, else refused); TEMPBAN = BAN + duration. `/purge` always replies privately and never auto-deletes; `/purge` and `/slowmode` default to ModerateMembers.
- **Jobs:** `mod.unban` (`mod.unban:{guildId}:{userId}`), `mod.expire` (`mod.expire:{infractionId}`); run with the module off.
- **Dashboard:** source `dashboard` (in `MOD_SOURCES`, checked like `command`: the acting user's roles, immunity and self-moderation; the DM may name them). Tasks `mod.action`, `mod.editCase`, `mod.clearWarnings` (`src/services/dashboardTasks/moderation.js`) do what `/warn` … `/case clear-history` do and re-check the module and the user's rights.
- **Hooks:** `guildReady:moderation` runs `syncGuildBans` (also guildCreate; Redis `mod:bansync:{guildId}`, 6 h).

### 🤖 Auto-Moderation — `automod`
- **Commands:** `/automod` ADMIN (groups `words` `patterns` `domains` `exempt` `honeypot`); `words`/`patterns` replies ephemeral.
- **Code:** `src/plugins/automod.js`, `src/services/automodService.js`. Rules: badWords repeatedText invites links caps emojis spoilers mentions zalgo spam. Actions: off delete warn delete_warn timeout kick ban (punishments via `executeModAction`). `automodConfig` v2 top level: `version rules badWords badWordPatterns blockedDomains allowedDomains exemptRoleIds exemptChannelIds`. Staff bypass: `isImmune`, MODERATOR, Manage Messages.
- **Bad words:** whole-word, but a run of `_` at the edge of a word (`_bad_`, `__bad__`, `bad_`) is Discord italics/underline and counts as a boundary (`textForWords`); `snake_bad_word` and an escaped `\_` stay word characters. A listed word written only in Han/Hiragana/Katakana/Thai/Lao/Khmer/Myanmar (no word spaces; Hangul is spaced) matches as a substring.
- **Hooks:** `messageCreate:automod` (first), `messageUpdate:automod`; after a delete: `ctx.stop('automod')`, `ctx.state.automodAction = { rule, deleted }`. A failed delete never punishes (except the honeypot).
- **Honeypot:** `automodConfig.honeypot = { channelIds (≤ `LIMITS.AUTOMOD_HONEYPOTS`, text/announcement only, a thread counts as its parent, a category never), action softban|ban|kick|timeout (default softban), timeoutSeconds }`. Not a `RULE_KEYS` rule. Checked first in `runAutomod`: works with every rule off, ignores `exemptChannelIds`, skips edits; owner, staff and `exemptRoleIds` bypass. Outcome via `honeypotOutcome`: always deletes, punishes even if the delete failed, ban/softban clear 1 day (`HONEYPOT_DELETE_MESSAGE_SECONDS`), no in-channel notice. `/automod honeypot add [channel] [action] [timeout] [warning]` (no channel: creates `#do-not-post` at position 0, needs Manage Channels) and `remove channel`; both forget deleted channels. Dashboard: virtual field `automodHoneypot`.

### 🎭 Reaction Roles — `reactionroles`
- **Code:** `/reactionrole`, `src/plugins/reaction-roles.js`. `RRLayout` BUTTONS, SELECT, REACTIONS (emoji reactions; `attach` binds an existing message).
- **customIds:** `rr:{groupId}:{roleId}`, `rr-select:{groupId}`; module-gated, no level check.
- **Hooks (id `reaction-roles`):** the four messageReaction* events; `always`: `messageDelete`, `roleDelete`.
- **Gotchas:** `safeReply` after `deferUpdate` follows up, so the personal select uses `editReply`.
- **Role templates:** `template:pronouns|colors|age|regions|platforms|dms|pings|timezones-us|timezones-world` (`/reactionrole create`, and the dashboard's create-only `template` field) use `ROLE_TEMPLATES` (`src/utils/roleTemplates.js`; the timezone sets come from `TIMEZONE_ROLE_TEMPLATES` in `src/utils/timezones.js` and have `linksZones`). Each template has its own `panel` (mode, layout, texts), roles (name, label, emoji, optional color) and an optional `note` for the admin. `setupRoleTemplate` (`src/services/roleTemplateSetup.js`) checks everything first (Manage Roles, `checkAssignableRole` on reused roles, Discord's 250-role cap, and `LIMITS.TIMEZONE_ROLES` for timezones), reuses roles by name or creates them with no permissions (and the template color), and links timezone roles in `GuildSettings.timezoneRoles`. Template panels are buttons or a dropdown, never emoji reactions (so up to 25 roles); a timezone panel is always Unique. When a timezone template gains roles, append the old zone list to `TIMEZONE_TEMPLATE_PAST_ZONES` (never edit one): the gated `guildReady` hook runs `upgradeTimezonePanels`, which adds the new roles (reused by name if free or linked to the same zone, else created) in template order to every Unique dropdown/button panel whose linked zones are exactly a past set, links them and re-renders the panel; a panel an admin changed never matches, an upgraded one no longer does, and any failed check skips the panel before creating anything. New color roles land at the bottom, so the colors note tells admins to drag them up. The dashboard saves the panel empty and runs `rr.roleTemplate`, which fills and posts it; a refusal deletes the empty panel.

- **Commands:** `/levelconfig` ADMIN (settings, plus the `xp` group: give, remove, set, reset, view); `/rank`, `/leaderboard`. `/levelconfig xp give target:@Role` caps at 5,000 members.

### 🏷️ Custom Commands — `customcommands`
- **Commands:** `/tag` (not gated: `execute()` refuses everything outside the `trigger` group while the module is off; writes ADMIN), `/tag trigger` group (ADMIN).
- **Code:** `src/plugins/custom-commands.js`, `src/services/tagService.js`.
- **Prefix:** `customPrefix` (default `!`); `/settings prefix off` stores `''` (`/tag use` still works). Upgraded guilds that have tags start answering `!name`.

- **Admin rules (`/tag`):** a `send` action needs View Channel + Send Messages for the admin in the target (owner/Administrator exempt); a tag giving or taking a role at or above the admin's highest role cannot be edited, toggled or have its cooldown, permissions, actions or replies changed by them (owner exempt; dashboard: `checkStoredRoles` on the `tags` collection).

### ⚙️ Automations — `automations`
- **Commands:** `/automation` ADMIN.
- **Code:** `src/plugins/automations.js`, `src/services/automationService.js`; button prefix `automation` (`automation:{automationId}:{buttonIndex}`). 8 hooks, id `automations`.
- **Loop guard:** bots never trigger message events, chain depth <=3, 30 runs/10 s per guild, cooldown `automation:cd:{guildId}:{automationId}:{userId}` (given back when the budget or the 25-run queue refuses the run).
- **Import:** `/automation import` refuses GIVE/TAKE roles at or above the importer's highest role (owner exempt), like `action add`; it also needs the channel access and role-ping rights below, and replacing an automation that gives such a role is refused.
- **Admin rules:** a send/repost/thread target needs View Channel + Send Messages (Create Public Threads for threads) for the admin (owner/Administrator exempt; presets and import too); a role mention the admin could not ping is refused at config time (`pingableRoleIds`; the dashboard applies it with `pingRoleProblem` to message texts, the Welcomer text and saved embeds it adds: owner, Administrator, Mention Everyone and the bot owner may ping any role, a role the automation already pinged is kept); an automation giving or taking a role at or above the admin's highest role cannot be edited, enabled, disabled or changed by them (owner exempt; dashboard: `checkStoredRoles` on the `automations` collection).
- **Privacy at run time:** REPOST, and SEND_MESSAGE/SEND_EMBED/SEND_IN_THREAD/CREATE_THREAD texts with `{message.content}` or `{message.old_content}`, skip (problem logged) when the message's channel is hidden from @everyone and the target is not (`src/utils/privacyGuards.js`).

### 🌐 Auto-Translate — `translation`
- **Commands:** `/autotranslate` ADMIN.
- **Code:** `src/plugins/translation-fixes.js` (hook last in `messageCreate`), `src/services/translationService.js`.
- **Providers:** `TRANSLATE_PROVIDER` `google` (default) or `libretranslate` (`LIBRETRANSLATE_URL`, `LIBRETRANSLATE_API_KEY`); else warns, uses google. Traditional Chinese is `zh-tw`; aliases `iw nb zh-cn zh-hant fil`; the first 1,000 characters are translated, up to 1,000 shown per language.
- **Channel list:** `saveTranslateChannel` (translationService) does the cap check and the insert under a per-guild advisory lock (`translate-channels:{guildId}`), shared by `/autotranslate` and the dashboard store; `refreshTranslateCache` bumps a per-guild generation so a read that began earlier never re-memoises a stale list.
- **Redis:** `tr:{provider}:{target}:{sha1}` (1 h), `translate:{provider}:pausedUntil`; a 429 pauses (30 min Google, 1 min LibreTranslate).
- **Activity:** `src/services/translateStatsService.js` `recordTranslation` counts each auto-translate reply that was sent and each `/translate text` in a server (never DMs) in `TranslateStat`: per channel, `via` `auto|command`, `direction` `from` (detected language, `und` when none) or `to` (each target shown), `count` clamped to int4. One `INSERT … ON CONFLICT` per message, unawaited, never throws; counts only, never text. The dashboard's read-only `translateStats` list shows it per channel.

### 📨 Invite Tracker — `invites`

### ⏰ Reminders — `reminders`
- **Code:** `/reminder`, `src/plugins/reminders.js`.
- **Job:** `reminder.fire`, dedupe `reminder:{reminderId}`, recurring. **Hooks (`always`):** `channelDelete:reminders`, `guildReady:reminders`. No Redis.
- **customIds:** modal `reminder-modal:{reminderId}`, `module: null`; the handler re-checks ADMIN.
- **Gotchas:** ignores `job.runAt`; sends only a due occurrence within the late tolerance (TIME_OF_DAY 15 min, INTERVAL min(15 min, interval/2), ONE_SHOT 60 min). The first occurrence after a `GuildSettings.timezone` change may skip once; `/reminder resume` re-syncs.
- **Send failures:** a transient one (Discord 5xx, 429, network error, timeout) hands back the occurrence's claim and throws, so the scheduler retries with its backoff (`maxAttempts` 10) while the retry still fits the late tolerance; the final attempt never throws (recurring reschedules, ONE_SHOT finishes). Permanent codes (50001/50013/10003/10013/50007/50035) are never retried. Every send carries a per-occurrence `nonce` + `enforceNonce`, so a retry cannot post twice; a timed-out send is retried only on the first two (<= 60 s) backoff steps.

### 📊 Polls — `polls`
- **Code:** `/poll` (MODERATOR), `src/plugins/polls.js`.

### 🌟 Starboards — `starboard`
- **Code:** `/starboard`, `src/plugins/starboard.js`.
- **Hooks (id `starboard`):** the four messageReaction* events, `messageUpdate`; `always`: `messageDelete`, `messageDeleteBulk`, `channelDelete`.
- **Gotchas:** staff-deleted reposts stay `blocked`; NSFW needs `allow_nsfw` and an age-restricted board; board-channel messages never count. Syncs of one message are spaced `SYNC_SPACING_MS` (1.5 s), or `REPOST_SYNC_SPACING_MS` (10 s) once it has a live repost (each sync re-reads every reactor over REST); the last sync of a burst always runs.

### 🎂 Birthdays — `birthdays`

### 🏆 Achievements — `achievements`

### 🪙 Economy — `economy`
- **Commands:** `/balance` `/daily` `/pity` `/work` `/pay` `/richest` `/shop` `/inventory` `/use`; admin: `/economy-admin` (coins, item, config and `boost` groups; boosts: up to `LIMITS.ECONOMY_BOOSTS`; a boost multiplies one `/daily` or `/work` payout only).
- **Models:** PER-SERVER `EconomyAccount`; legacy global `UserEconomy` is read-only. `getAccount(guildId, userId, settings)` creates an account lazily, copying the global balance ONCE (`importedGlobal`, unless `economyImportGlobal` is false), else `economyStartingBalance`. `economyConfig(settings)` reads the rest (`economyGameChannelIds` + `economyGameChannelMode` ALLOW|DENY, `economyMaxPayout` = net-winnings cap).
- **Money safety:** every balance write is ONE SQL statement (`::bigint` maths, `LEAST` cap or conditional `WHERE`), clamped to `COIN_MAX`; no read-modify-write in JS.
- **Casino API (`src/services/economyService.js`):** `tryLockCasino`/`unlockCasino` (sync, in memory, one game per member per server); `reserveBet` debits first; `settleBet` credits the GROSS payout at most once and REQUIRES the `stake` option (it retries only on `failedBeforeSend` errors: a lost response is never retried); `gameChannelCheck`.
- **Refunds:** `refundPurchase` returns the full price, clamped to `COIN_MAX` only (not the server's `economyMaxBalance`), so a buyer already at the cap loses nothing.
- **Plugin:** `src/plugins/economy.js`: only the `coins` provider, no hooks. `economyPurchase` fires from `/shop buy` ONLY. Use-on-buy ROLE buys are serialised per member and re-check the role on a forced member fetch (two buys sent together used to both pass).

### 🎮 Games — `games`
- **Commands:** `/blackjack` `/roulette` `/slots` are `module = 'economy'` (escrowed bets); the rest (`/games` with `list` `rps` `numguess` `tictactoe`, and `/scrabble`) are `games`-gated. `/games list` lists `client.commandCategories` entries `games`, one line per subcommand for commands that have them (`games rps`, `scrabble word`); a new game needs its emoji in `GAME_EMOJI`, keyed by the command path (`src/commands/games/games.js`). `/slots` pays 15/11/7/5/4/3x per line (💎 7️⃣ 🍇 🍒 🍋 🍎), RTP 95.02 % (derivation in `slots.js`; `test/review-economy.test.js` keeps it in 94-96 %).
- **customIds:** collector prefixes `ttt` `ttt-ch` `rps` `scrabble-ch` `bj`; persistent `scrabble-rack:{gameId}` (registered by `src/plugins/games-fixes.js`).
- **Scrabble:** games live in memory (`activeGames` in `src/services/scrabbleService.js`), so a restart ends them; turn timeout = forfeit. `/scrabble start|word|pass|exchange|resign|help`; `?X` plays a blank as X. Optional dictionary `assets/dictionaries/words.txt` (operator-supplied, e.g. ENABLE list, not shipped, ~10-15 MB RAM per shard); without it any A-Z word passes.

### 📰 Social Feeds — `feeds`
- **Commands:** `/feed` (ADMIN); `LIMITS.FEEDS` 30.
- **Code:** `src/services/feedService.js`, `src/services/feedParsers.js` (`fast-xml-parser`), `src/plugins/feeds.js`; model `Feed`, `FeedType` RSS|YOUTUBE|REDDIT|BLUESKY|PODCAST.

- **Code:** `src/services/confessionService.js` (rules, `RAW_SQL`), `src/plugins/confessions.js` (hooks `messageDelete:confessions` + `channelDelete:confessions`, both `always`; button `confession` = `confession:new` (panel) and `confession:{id}:approve|reject` (review message), modal `confession-modal`, field `confession-text`). Model `Confession`; settings `confessionChannelId|ReviewChannelId|AllowImages|BlockLinks|CooldownSeconds|BlockedUserIds`; `LIMITS.CONFESSION_LENGTH|IMAGE_BYTES|BLOCKED_USERS`.
- **Rules:** number and cooldown under `pg_advisory_xact_lock('confession-number:{guildId}')`. Review channel set: row PENDING and a review message (number, text, image, Approve/Reject, never the author); the buttons re-check MODERATOR+ and CLAIM the row (`updateMany where status PENDING`) so two moderators cannot both post; a failed post gives the claim back. Images: `safeFetchImage` (size cap), re-uploaded as `confession.<ext>` (extension from the bytes; the member's file name is never used); approve re-fetches the review message for a fresh copy. Links (URLs, `www.`, Discord invites, also zero-width-disguised) refused while `confessionBlockLinks`. The public post is stamped with the posting time, not the writing time.
- **Staff:** `block`/`unblock` edit `confessionBlockedUserIds` (`updateSettingsWith`) and answer identically whether or not the author was already (un)blocked; the setup embed shows no count (a count would link two confessions to one author); at the 500 cap a block is refused whoever the author is. `reveal` first sends a moderation-log entry (`modLogChannelId`: the admin and the number, never the author) and only then shows the author in the admin's ephemeral reply; with no usable mod log, or if the entry cannot be sent, nothing is revealed. `delete` claims the row (DELETED) before removing the post, so a racing approve cannot publish it; a post Discord will not delete gives the claim back.
- **Hooks:** `messageDelete` nulls `messageId`/`reviewMessageId` (row stays); `channelDelete` of the confession channel unsets `confessionChannelId`; deleting the REVIEW channel unsets BOTH channels and orphans the pending queue (fail closed: unsetting only the review channel would publish unreviewed). Posts in a deleted channel lose `messageId`.
- **Gotchas:** `authorId` is read only for the cooldown, block and reveal, and never logged: Prisma errors echo their arguments, so DB failures are logged by `errTag` (name and code). No retention or purge of `authorId` in v1. Uploaded images are re-sent byte for byte (Discord strips location EXIF itself; the bot does not re-encode). The row has no review-channel id, so `delete` closes a pending review message only if it is in the CURRENT review channel. Panel messages are not tracked in the database. Timing (a post appearing right after a member was active) is outside the bot's control.

### 🧵 Auto Threads — `autothreads`
- **Commands:** `/autothread add channel [name] [archive] [close_button]|remove channel|list|publish add channel|publish remove channel` (ADMIN, `gated: false`, works while the module is off and says so). `add` on a listed channel changes only the options given. `name` is checked for unknown placeholders; `publish` takes announcement channels only.
- **Code:** `src/services/autoThreadService.js` (list parsing, names, `createThread`, `publishMessage`, the crosspost limiter, list changes), `src/plugins/auto-threads.js` (hooks `messageCreate:auto-threads` after automod and before sticky, `botMessage:auto-threads`, `channelDelete:auto-threads` always; button `autothread:close:{starterUserId}`). No table, no job. Lists: `GuildSettings.autoThreadChannels` (`[{ channelId, name, archiveMinutes: '60'|'1440'|'4320'|'10080', closeButton }]`, `LIMITS.AUTOTHREAD_CHANNELS`) and `autoPublishChannelIds` (`LIMITS.AUTOPUBLISH_CHANNELS`), written with `updateSettingsWith` (entries the dashboard stored are never rewritten) and on the dashboard.
- **Threads:** a member message in a listed text or announcement channel (not a thread or forum) gets `message.startThread`. Name = the template through `placeholderParser` with `vars` overriding `{user}` (display name), `{content}` (first line with words of `cleanContent`, markdown, mention/emoji tags and spoilers stripped), `{channel}` (channel name) and `{date}` (UTC `YYYY-MM-DD`); at most 100 characters, empty = the display name. Needs Create Public Threads (+ Send Messages in Threads with the close button) or it skips and logs once per channel per hour. The Close button (starter, Manage Threads or bot Moderator) edits its message, then archives (and locks when the bot has Manage Threads) in one `thread.edit`.
- **Publishing:** a post in a listed announcement channel (member via `messageCreate`, bot or webhook via `botMessage`) is crossposted unless it is a system message, poll, forward, a bot's "thinking" placeholder (`Loading`), another edit (`edited`), already published or itself a crosspost; a deferred bot reply is published by the edit that answers it (`wasLoading`). Needs Manage Messages. At most 10 per channel per sliding hour (`createPublishLimiter`, in memory); past that the post stays unpublished and one line is logged per hour.
- **Hot path:** both filters are synchronous: channel type, then `peekSettings` and a `WeakMap`-cached parse of the lists (a frozen settings object is replaced on every change). No settings memo = pass, the handler loads them. Crossposts and the close-button post run detached (`detach`) so a queued 429 never holds up `sticky`.
- **Gotchas:** the close button is module-gated (off = "turned off" notice); turning the module off or removing a channel leaves existing threads alone; the crosspost counter resets on restart; a message with no text (attachment only, or no Message Content intent) gets the author's display name as its title.

### 🎙️ Voice Roles — `voiceroles`
- **Commands:** `/voicerole add|remove <channel> <role>`, `any add|any remove <role>`, `list`, `sync` (ADMIN, `gated: false`; every subcommand is admin so none needs the module-off refusal, only `sync` refuses while the module is off). Settings `voiceRoleLinks` (`[{ channelId, roleId }]`, `LIMITS.VOICE_ROLE_LINKS`), `voiceRoleAnyRoleIds` (`LIMITS.VOICE_ROLE_ANY`), `voiceRoleIgnoreAfk`; edits go through `updateSettingsWith` (cap and duplicate check under the row lock).
- **Code:** rules, role changes, reconcile and settings edits in `src/services/voiceRoleService.js` (`managedRoleIds(settings)` is the pure "roles this module owns" helper); hooks `voice-roles` on `voiceStateUpdate`, `guildReady` and `channelDelete` + `roleDelete` (`always`) in `src/plugins/voice-roles.js`. No models, prefixes or jobs.
- **Rules:** a member's desired roles = links whose channel is their channel or its category + the any-list while in voice; none when not in voice, or in `guild.afkChannelId` with `voiceRoleIgnoreAfk`. Every join/leave/move recomputes from the CURRENT voice state (`guild.voiceStates.cache`) and adds the missing desired roles, then removes held managed roles that are not desired; one role per call with an audit reason, serialised per member. Adds use `checkAssignableRole` (no managed, above-bot or dangerous role); removes only need the bot to be able to reach the role. Bots are skipped.
- **Reconcile:** `guildReady` (detached, one guild at a time) and `/voicerole sync` run the same bounded pass (`RECONCILE_MAX` 1000 members, concurrency 3, caches only): everyone in voice gets their roles, cached holders of a managed role who are not in voice lose it. One pass per guild at a time.
- **Gotchas:** role calls are single-role PUT/DELETE (the array forms PATCH the whole role list from the cache and could drop another hook's role). discord.js leaves `member.roles.cache` untouched until the gateway echo, so the roles just changed are remembered for 20 s (bounded) and a fast A -> B -> A hop still ends right. Turning the module off, removing a link, or editing the settings on the dashboard leaves roles where they are: they are fixed at the member's next voice change or by `/voicerole sync`; members holding an unlinked role keep it. Moving a voice channel to another category is not noticed until the member's next voice change or a sync. Deleting a linked channel or category drops its links and, while the module is on, removes their roles from cached holders not entitled to them by another link or the any-list.

### 📣 Bump Reminders — `bumps`
- **Commands:** `/bumps status|leaderboard` (MEMBER; refuse with the router's "Module Disabled" embed while the module is off), `setup [channel] [role] [thanks] [coins]` and `reset [user]` (ADMIN via `subcommandPermissions`; `gated: false` so it can be set up first; `reset` with no user asks Clear all / Cancel with `awaitConfirm`). Settings: `bumpChannelId`, `bumpRoleId`, `bumpReminderMessage`, `bumpThanks`, `bumpThanksMessage`, `bumpRewardCoins`.
- **Code:** `src/services/bumpService.js`, `src/plugins/bumps.js`, `src/commands/community/bumps.js`; `BumpState` (`guildId+site`) and `BumpCount` (`guildId+userId`); hooks `botMessage:bumps` (module-gated, sync filter on the author id), `channelDelete` / `roleDelete` (`always`, unset the channel / role); job `bump.remind` (one-shot, dedupe `bump.remind:{guildId}:{site}`, `onConflict: 'replace'`). No prefixes, no `guildReady` hook.
- **Detection:** `BUMP_SITES` (`disboard`: bot id, name, 2 h cooldown, pure `isSuccess`). Success = an embed saying "Bump done" or whose image URL contains `bot-command-image-bump`; a "Please wait ... until the server can be bumped" text always wins. The bumper is `interactionMetadata?.user ?? interaction?.user` (never a bot). Message ids are processed once (500 remembered) and the state write only accepts a bump newer than the recorded one.
- **Rules:** a bump upserts the state (`remindedAt` null), schedules the reminder, then increments the count with one clamped raw upsert (`LEAST(count::bigint + 1, XP_MAX)`), then thanks (`allowedMentions.users` = the bumper only; `{user}` `{next}` `{count}` `{site}`) and grants `bumpRewardCoins` (`module-disabled` / `unavailable` ignored). An unknown bumper still sets the reminder but is not counted, thanked or paid. `bump.remind` posts only while the module is on, in `bumpChannelId` else the last bump's channel, pinging `bumpRoleId` only when `pingableRoleIds` allows it (mentionable, or the bot has Mention Everyone); `allowedMentions` is `{ parse: [], roles: [thatRole] }`.
- **Gotchas:** the job claims `remindedAt` before posting and releases it when nothing was posted (a retry never reminds twice; permanent Discord errors 10003/50001/50013/50083 end the job quietly, others retry); a job that wakes before `nextBumpAt` reschedules itself. The job is one-shot and persisted, so nothing is re-seeded on `guildReady` and dashboard edits need no job change (settings are read at send time). Bumps made while the module is off are not seen, so no reminder follows; the bot must be able to view the channel where members run `/bump`.
- **Known limits:** only Disboard; a deferred Disboard answer is read when it is edited into "Bump done" (`botMessage` with `edited: true` from `messageUpdate`); scheduling failures are retried once and then logged (the reminder is lost until the next bump).

### 💾 Server Backups — `backups`
- **Commands:** `/backup create [name] | list | info | export | status | delete | restore [mode]` (ADMIN, `gated: false`, everything works while the module is off; replies are ephemeral; `backup` autocompletes name + date). `delete` and `restore` are SERVER OWNER only (`interaction.guild.ownerId`, NOT `PERMISSION_LEVELS.OWNER`), checked before any await and again in the persistent buttons `backup:restore:{backupId}:{missing|full}` / `backup:cancel` (`module: null`; the confirmation expires 5 minutes after its message).
- **Code:** `src/services/backupService.js`, `src/utils/guildSnapshot.js` (snapshot v1 + restore engine), `src/plugins/backups.js` (hook `guildReady:backups` always, jobs `backup.auto`, `backup.restore`). Rows: `ServerBackup` (`data` = roles with `@everyone`'s permissions, categories, channels, overwrites as decimal strings; no threads, messages, members, emojis or bot settings; refused over `BACKUP_BYTES`).
- **Restore:** never deletes anything, never runs in the interaction. Confirm schedules `backup.restore` (dedupe `backup.restore:{guildId}`, `onConflict: 'keep'`: a second Confirm while one is live is refused). Each run does ~10 API calls / 18 s and saves `{ backupId, mode, phase, cursor, idMap, made, counts, errors, startedById, channelId, startedAt }` via `{ nextRunAt: +2 s, payload }`; phases roles, role order, categories, channels, channel order (full), overwrites (one PUT per target, never `permissionOverwrites.set`). `missing` only recreates what is gone; its channels are created WITH their @everyone and role overwrites (members follow one by one), and a channel that still exists only gets the overwrites of RECREATED roles, added where it has none for that role, never changed; `full` also edits what exists (never roles above the bot or managed ones). The bot gives only permissions it has and keeps the bits it cannot control; the rest is reported in the summary posted in the starting channel (DM fallback). Needs BOTH Manage Roles and Manage Channels: `/backup restore` and Confirm refuse without them, and a batch that finds one gone stops (FAILED, resumable) instead of making channels without their permissions.
- **Resume and idempotency:** every decision is made from the snapshot plus the guild's current state; a batch repeated from an old payload adopts roles/channels created after `startedAt` with the same name (type and parent for channels) instead of making them again; a call that times out is retried in the next batch (5 stalls, then reported and skipped); an in-process guard makes a retry that overlaps a still-running batch wait without touching the payload; a job 30 minutes late (bot away) is stopped, not resumed. A finished restore stores old id -> new id in `data.idMap` (never exported), and the next restore seeds from it, so restoring twice does not make copies. A restore that stopped (more than 30 minutes late, or a missing permission) or FAILED keeps its job row FAILED; the next restore of the same backup continues from it (`carriedFrom`: `idMap` and `made`, not the start time, so nobody else's same-named role or channel is adopted).
- **`backup.auto`:** recurring, seeded on `guildReady` when the module is on or `backupIntervalHours > 0`, and by any `/backup` command; reads the settings every run and never waits more than an hour, so a dashboard change is picked up. Makes an automatic backup when the module is on, the interval is > 0 and the newest automatic one is older than it; then `pruneAutomatic` (only `automatic: true` rows beyond `backupKeep`). Paused while a restore is live.
- **Gotchas:** manual cap `BACKUPS_MANUAL` is counted under a per-guild mutex (one shard owns a guild). Turning the module on only from the dashboard in a guild that has no `backup.auto` job waits for a restart or any `/backup` command. Gradient role colours keep only the primary colour. Mode `missing` does not touch channels that still exist, overwrites added after the backup stay in `full`.

### Core commands (no module)
- `/help`, `/module` (ADMIN): `/help` hides commands above the caller's level or of disabled modules; custom commands show as `!name` (`/tag use name:x` when `customPrefix === ''`).
- `/settings show|timezone|color|prefix|urban|timezone-role add|remove|list` (ADMIN): timezone IANA or `UTC`; `timezone-role` links roles to zones in `GuildSettings.timezoneRoles` (`[{ roleId, zone }]`, `LIMITS.TIMEZONE_ROLES`, via `updateSettingsWith`; deleted roles are dropped on the next write and ignored on read); with no `zone` it reads the role name (`zoneFromRoleName`: CST, EST/EDT, UTC+1); also editable on the dashboard General page (`timezoneRoles` objectList); `embedColor` only for info/neutral embeds (`applyGuildColor`/`guildEmbed`), never 0; `customPrefix` 1-5 code points, custom commands only, `off` stores `''`.
- `/info user|server|role` (MEMBER); `/emoji add|list|delete` (ADMIN + Manage Expressions).
- `/translate text|detect|languages`: MEMBER, also work in DMs.
- `/timestamp when [style] [public]` (MEMBER): `parseWhen` (`src/utils/time.js`) reads the text in the caller's zone, resolved by `resolveTimezone` (`src/utils/timezones.js`): own `UserTimezone` → highest held timezone role → server `timezone` → UTC; a trailing abbreviation, `utc+2` or Region/City in the text wins. Private by default (every style with its code); `public:true` posts the stamp. Autocomplete previews the reading (memo/Redis only, no Postgres).
- `/timezone set|show|clear` (MEMBER, ephemeral): personal zone in `UserTimezone` (global, no guild FK) via `src/services/userTimezoneService.js` (memo 30 s → Redis `usertz:{userId}` 1 h → Postgres). Abbreviations (`ZONE_ABBREVIATIONS`: CST → America/Chicago, DST included) are accepted; ambiguous ones (IST, AST) and fixed offsets are refused.
- `/owner` (MEMBER): replies in plain content pinging `BOT_OWNER_ID` (only that user is in `allowedMentions`); ephemeral error when unset.
