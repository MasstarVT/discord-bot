# feat-translation: public API (from its author)

The crate was an empty skeleton after the crash, so it was ported from scratch. All 10 JS files are now in Rust, with one entry point, register(). File mapping (crate root rust/crates/feat-translation):
- src/services/translationService.js -> src/translation_service.rs. Covers the language registry and normalisation, the Google GET/POST/chunked adapter, LibreTranslate with failover to a fallback server, the circuit breaker and the shared pause in Redis, request and embed sizing, the result cache (tr:{provider}:{target}:{sha1}), the channel-config memo, Redis cache and generation counters (guild:{g}:translateChannels), saveTranslateChannel (advisory lock and cap) and handleAutoTranslate.
- src/services/translateStatsService.js -> src/translate_stats_service.rs (statKeys, the multi-row TranslateStat upsert, recordTranslation).
- src/services/userTimezoneService.js -> src/user_timezone_service.rs (memo, usertz:{u} cache, UserTimezone upsert and delete, resolveMemberTimezone).
- src/plugins/translation-fixes.js -> src/plugins/translation_fixes.rs.
- src/plugins/autotime.js -> src/plugins/autotime.rs.
- src/commands/admin/autotranslate.js, admin/autotime.js, utility/translate.js, utility/timestamp.js, utility/timezone.js -> src/commands/{autotranslate,autotime,translate,timestamp,timezone}.rs.
- src/intl_data.rs is generated by rust/fixtures/gen/feat-translation-intl.mjs from Node's ICU. It holds the language display names and the likely-Latin-script codes that languageName and reconcileDetected need.

HTTP goes through an injectable HttpTransport (reqwest in production). Tests use a fake transport with canned responses and never touch the network.

Golden fixtures come from rust/fixtures/gen/feat-translation-golden.mjs and are written to rust/fixtures/golden/feat-translation/golden.json. They cover codes, names, choices, text cleaning and splitting, embeds, error embeds, request URLs, bodies and headers, cache keys, values and TTLs, statKeys, RAW_SQL, and the autotime and timestamp texts. rust/fixtures/gen/feat-translation-js.mjs is the JS side of the cross-language database and Redis tests.

Tests: tests/translation.rs (43) and tests/autotime.rs (18). They include ports of translation-fixes.test.js, autotime.test.js and the service and command parts of timestamp.test.js and translate-stats.test.js, golden replays, the commands through the router, and both directions JS<->Rust for TranslateChannel and its Redis cache, TranslateStat, UserTimezone and the usertz cache.

## API

Modules are public as feat_translation::{translation_service, translate_stats_service, user_timezone_service, plugins, commands}. Every function takes &App.

For feat-events, in user_timezone_service:
- get_user_timezone(&App, user_id: &str, cache_only: bool) -> Option<Option<String>>. None means unknown (lookup failed or cache-only miss), Some(None) means no zone saved, Some(Some(zone)) is a saved zone.
- peek_user_timezone(&App, user_id) -> Option<Option<String>>.
- set_user_timezone(&App, user_id, zone) -> Result<(), DbError>.
- clear_user_timezone(&App, user_id) -> Result<bool, DbError>.
- resolve_member_timezone(member_roles: &[String], guild: Option<&serenity Guild>, settings: Option<&GuildSettings>, personal: Option<&str>) -> bot_util::timezones::ResolvedTimezone.
- member_role_ids(Option<&Member>) -> Vec<String>.
- user_timezone_key(user_id); cache_value / read_cache_value hold the JS {zone} shape.

translation_service, for the dashboard and others:
- get_guild_translate_config(&App, g) -> Result<IndexMap<channelId, Vec<lang>>, DbError>.
- get_channel_targets(&App, g, ch) -> Option<Vec<String>>.
- refresh_translate_cache(&App, g); invalidate_translate_cache is an alias.
- save_translate_channel(&App, g, ch, &[String], update_existing) -> Result<SaveOutcome::{Saved{created,row} | Limit{count} | Exists}, DbError>. The caller runs ensure_guild_settings first and refresh_translate_cache after.
- load_rows(pool, g) -> Vec<ChannelRow>; channels_key(g).
- translate_text(&App, text, target, source ("auto" to detect), max_chunks) -> Result<Translated{text,detected}, TranslationError>.
- translate_to_targets(&App, text, &[targets], deadline_ms: Option<i64>) -> TargetsOutcome.
- detect_language(&App, text) -> Result<DetectedLanguage{code,name}, TranslationError>.
- describe_translation_error(&App, Option<&TranslationError>) -> DescribedError{level,log,embed}.
- load_language_support(&App, force) -> Option<Vec<String>>; warm_language_support; is_supported_target -> Option<bool>; get_languages; language_choices(&App, query) -> Vec<LanguageChoice{name,value}>.
- Pure helpers: normalize_lang_code, resolve_language_input, suggest_language, normalize_target_list -> TargetList{valid,invalid}, language_name(Option<&str>), lang_flag, to_google_code, to_lt_code, is_link_only, clean_for_translation, has_translatable_text, prepare_auto_input(_for), clamp_for_request, split_for_requests, split_for_embeds, is_echo, balance_markdown, format_target_line, build_auto_translate_embed(&AutoEmbedArgs), build_auto_reply_payload, reconcile_detected, result_key.
- Pause: translation_paused, pause_remaining_ms, paused_key.
- Hook body: handle_auto_translate(&App, AutoCtx, reply closure).
- raw_sql() -> Vec<RawSql>; LANGUAGES table; constants as in the JS.
- Provider and test seam: provider_name, provider_label, config, configure(ConfigOverride), reset, set_transport(Arc<dyn HttpTransport>), prime_channel_config.

translate_stats_service: record_translation(&App, g, ch, StatVia::{Auto|Command}, detected: Option<&str>, targets), which never fails; stat_keys, record_sql, record_values, raw_sql; UNKNOWN_LANG, DIRECTION_FROM, DIRECTION_TO.

plugins::autotime: is_ignored_channel, may_answer, answer_text, zone_hint_text, author_zone, read_message, times_to_answer, reply_content, handle_message, ChannelInfo, TimeMessage.

commands::timestamp: future_day_example, rough_relative, suggest_when, build_timestamp_embed, load_caller_zone, STYLES, EXAMPLES.

commands::autotime: HOW_IT_WORKS, timezone_roles_line.

commands::translate: languages_embed.

## Known gaps

- src/plugins/translation-fixes.js hook / translationService.handleAutoTranslate: ctx.state.automodAction?.deleted is read as serde_json::Value with a `deleted` bool, because feat-automod has not published a Rust type for the state value yet. If automod stores a different Rust type, that check misses. Messages automod deleted are still skipped through the deletion tracker (wasDeletedByBot).
- Throttles (createThrottle) in translationService, plugins/autotime.js (member, repeat and zone-hint cooldowns) and translateStats use bot_util's Throttle, which runs on tokio Instant rather than the app clock. Production behaviour is the same, but tests cannot move those cooldowns with the app clock.
- translationService.translateText cache hit: a non-string `d` in a cached {t,d} value reads as null. JS would pass the raw value through.
- buildAutoReplyPayload and autotime reply: serenity serializes allowed_mentions as {parse:[],users:[],roles:[],replied_user:false}. The JS sends {parse:[],repliedUser:false}. Discord treats both the same.
- translationService.doFetch: network error messages come from reqwest rather than undici ('fetch failed'). They only appear in logs and in the failover reason.
- translationService.languageName: codes outside LANGUAGES use a generated ICU table of 2- and 3-letter codes. A hyphenated code outside LANGUAGES returns the raw code where Intl.DisplayNames would name it. No caller can reach this, because normalizeLangCode only yields base codes or zh-tw.
- translationService.getLanguages: the langCache memo is dropped. It only saved work, and the output is identical.
- commands/admin/autotranslate.js and autotime.js (ignore add): when the interaction carries no resolved channel data, the channel type and name come from the guild cache. Discord always sends resolved data, so this only matters in tests.
