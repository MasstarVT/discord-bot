[feat-moderation, feat-automod] bot-core router (CommandInteraction option resolution): discord.js CommandInteraction.transformOption calls client.channels._add(resolved channel, guild) for every CHANNEL option, so code that later does guild.channels.cache.get(picked.id) always finds the picked channel. The Rust router does not add data.resolved.channels to the serenity cache, so every feature that reads a picked channel from the cache treats an uncached pick as missing. I worked around it in my crates with check_channel_usable_fetch / fetch_channel. Caveat: resolved channels are partial; they have no permission_overwrites, so a REST fetch is safer than caching the partial object.
